# Prompt Engineering (2026 Edition)

AIの回答精度はプロンプトの設計に大きく左右されます。現代のLLM（Claude 3.7, Gemini 2.0等）の特性を活かしたテクニックを紹介します。

---

## 1. 核心となる基本原則

### 最初に指示を置く
プロンプトの冒頭に、AIに何をさせたいか（要約、翻訳、コーディング等）を明記します。長いコンテキストを扱う場合、指示が最初にあることでAIは情報の処理優先度を正しく判断できます。

### 具体的・定量的であること
「なるべく短く」ではなく「3文以内で」、「速いコード」ではなく「O(N log N)の計算量で」といった具合に、具体的な数値を指定します。

### 「何をすべきか」にフォーカスする
「〜しないでください」という否定形の指示よりも、「〜してください」という肯定形の指示の方が、AIは意図を正確に汲み取りやすい傾向があります。

---

## 2. 高度なテクニック

### Chain-of-Thought (思考の連鎖)
「ステップバイステップで考えてください」と付け加えるだけで、複雑な論理推論の精度が向上します。特に計算やアルゴリズムの設計に有効です。

### Few-shot Prompting (具体例の提示)
「期待する形式」の入出力例を1〜2セット提示します。これにより、AIは抽象的な指示を具体的な「振る舞い」として理解します。

### System Prompts / Rules
`.cursorrules` や `GEMINI.md` にプロジェクト全体の「人格」や「制約」を定義しておくことで、個別のチャットで繰り返し指示する手間を省きます。

---

## 3. コンテキスト効率の最適化

現代のAIは100万トークン以上の入力を受け付けますが、情報が多すぎると重要な詳細を見落とす（Lost in the Middle）ことがあります。
- 関連するコードファイルのみを厳選して渡す。
- 外部ドキュメントはURLを渡すか、必要な部分のみを抜粋して渡す。

---

## 4. (参考) 旧時代のTips
以前のリポジトリで推奨されていたテクニックも、基本として依然有効です。
- 指示とコンテキストを `#` や `"` で区切る。
- ゼロショット（例なし）から始め、必要に応じて例を追加する。
